## 핵심 개념: 정확도와 유사도

### 정확도 (Accuracy)
**정확도**는 **전체 세그먼트 중에서 정답으로 판정된 것의 비율**을 측정하는 지표입니다.

#### 핵심 원리
정확도는 "맞다/틀리다"의 **이진 판단**을 기반으로 합니다:
1. 각 세그먼트 쌍을 평가하여 "정답"인지 판단
2. 정답 개수를 전체 개수로 나눔
3. 결과: $\text{Accuracy} = \frac{\text{정답 개수}}{\text{전체 개수}}$

#### 정답 판정 기준
세그먼트가 "정답"으로 판정되는 조건:
- **완전 일치**: 두 텍스트가 100% 동일
- **임계값 이상**: 유사도가 특정 임계값(예: 0.9) 이상
- **매칭 성공**: 원문과 번역이 올바르게 짝을 이룬 경우

#### 예시
```
전체 100개 세그먼트 평가:
- 완전 일치: 60개 → 정답
- 유사도 ≥ 0.9: 20개 → 정답
- 유사도 < 0.9: 20개 → 오답

정확도 = 80/100 = 0.80 (80%)
→ "100개 중 80개가 정확함"
```

#### 특징
- **개수 기반 평가**: "몇 개가 맞는가?"
- **이진 판단**: 각 항목은 정답(1) 또는 오답(0)
- **명확한 합격선**: 임계값을 넘으면 정답, 못 넘으면 오답

#### 주요 정확도 지표
- `avg_accuracy`: 원문 기준 정확도 (임계값 기반 판정)
- `avg_target_accuracy`: 번역문 기준 정확도
- `avg_exact_match`: 완전 일치율 (100% 일치만 정답)

### 유사도 (Similarity)
**유사도**는 **두 텍스트가 얼마나 비슷한지를 0~1 사이의 연속적 값**으로 측정하는 지표입니다.

#### 핵심 원리
유사도는 "얼마나 비슷한가?"를 **실수값**으로 표현합니다:
1. 각 세그먼트 쌍의 유사도를 계산 (0~1 사이 값)
2. 모든 유사도 값의 평균을 구함
3. 결과: $\text{Similarity} = \frac{\sum \text{유사도}_i}{n}$

#### 예시
```
전체 100개 세그먼트 평가:
- 세그먼트 1: 유사도 1.0 (완전 일치)
- 세그먼트 2: 유사도 0.95 (거의 일치)
- 세그먼트 3: 유사도 0.85 (상당히 비슷)
- 세그먼트 4: 유사도 0.70 (약간 비슷)
- ...
- 평균 유사도: 0.88

→ "평균적으로 88% 비슷함"
```

#### 비교 예시
```
참조 번역: "그는 학교에 갔다"

예측 번역: "그는 학교에 갔다"
→ 유사도: 1.0 (100% 동일)
→ 정확도 판정: ✓ 정답

예측 번역: "그는 학교로 갔다"
→ 유사도: 0.95 (조사만 다름)
→ 정확도 판정: ✓ 정답 (임계값 0.9 이상)

예측 번역: "그 사람은 학교에 갔다"
→ 유사도: 0.88 (주어만 다름)
→ 정확도 판정: ✗ 오답 (임계값 0.9 미만)

예측 번역: "그는 도서관에 갔다"
→ 유사도: 0.70 (장소가 다름)
→ 정확도 판정: ✗ 오답

예측 번역: "그는 학교를 좋아한다"
→ 유사도: 0.40 (의미가 다름)
→ 정확도 판정: ✗ 오답
```

#### 특징
- **연속적 평가**: "얼마나 비슷한가?"
- **실수값 표현**: 0.0 ~ 1.0 사이의 모든 값 가능
- **부분 점수**: 완벽하지 않아도 비슷하면 높은 점수

#### 주요 유사도 지표
- `avg_target_avg_similarity`: 번역문-원문 토큰 기반 유사도
- `avg_target_text_similarity`: 번역문 전체 텍스트 유사도
- `avg_source_jaccard`: 원문 Jaccard 유사도

---

### 정확도 vs 유사도: 핵심 차이

| 구분 | 정확도 (Accuracy) | 유사도 (Similarity) |
|------|------------------|-------------------|
| **질문** | "몇 개가 정답인가?" | "얼마나 비슷한가?" |
| **값의 종류** | 비율 (정답 개수 / 전체) | 평균 (유사도 점수 평균) |
| **판단 방식** | 이진 (정답 1 / 오답 0) | 연속 (0.0 ~ 1.0) |
| **계산 예시** | 80개 정답 / 100개 = 0.80 | (0.95+0.88+0.70+...)/100 = 0.82 |
| **임계값** | 사용 (예: 0.9 이상 = 정답) | 사용 안 함 (모든 값 평균) |
| **결과 해석** | "80%가 정확함" | "평균 82% 비슷함" |

---

### 구체적 예시로 이해하기

#### 시나리오: 100개 세그먼트 평가 결과

```
세그먼트별 유사도 분포:
- 1.0 (완전 일치): 50개
- 0.95~0.99: 15개
- 0.90~0.94: 10개
- 0.80~0.89: 15개
- 0.70~0.79: 7개
- 0.70 미만: 3개
```

#### 유사도 계산
```
평균 유사도 = (50×1.0 + 15×0.97 + 10×0.92 + 15×0.85 + 7×0.75 + 3×0.60) / 100
            = 91.55 / 100
            = 0.916 (91.6%)
```

#### 정확도 계산 (임계값 0.9 기준)
```
정답 개수 = 50 (완전 일치) + 15 (0.95~0.99) + 10 (0.90~0.94)
          = 75개

정확도 = 75 / 100 = 0.75 (75%)
```

#### 결과 해석
- **유사도 91.6%**: 평균적으로 매우 비슷함
- **정확도 75%**: 하지만 25%는 임계값 미달로 "오답" 처리

### 왜 두 지표 모두 필요한가?

#### 1. **정확도**는 합격/불합격 기준
- "이 정도는 정확해야 한다"는 최소 요구사항
- 법률, 의료 번역: "정답이 아니면 의미 없음"
- **예**: 정확도 95% = "100개 중 95개만 사용 가능"

#### 2. **유사도**는 품질의 전반적 수준
- "전체적으로 얼마나 좋은가?"
- 자연어 처리: "완벽하지 않아도 좋은 번역"
- **예**: 유사도 95% = "평균적으로 매우 우수"

#### 3. **병행 사용**으로 정밀 평가
```
시나리오 1: 정확도 95% + 유사도 96%
→ ✅ 거의 모든 세그먼트가 높은 품질

시나리오 2: 정확도 60% + 유사도 85%
→ ⚠️ 평균은 좋지만 40%는 임계값 미달 (불안정)

시나리오 3: 정확도 90% + 유사도 75%
→ ⚠️ 대부분 합격이지만 전반적 품질은 보통

시나리오 4: 정확도 50% + 유사도 60%
→ ❌ 절반이 불합격이고 품질도 낮음
```

---

### 실무 활용 가이드

#### 높은 정확도가 필요한 경우
- 법률 문서, 계약서
- 의료/제약 번역
- 기술 매뉴얼 (안전 관련)
- 공식 문서, 증명서

**권장 임계값**: `avg_accuracy` ≥ 0.95

#### 높은 유사도가 중요한 경우
- 문학 작품, 소설
- 마케팅 콘텐츠
- 챗봇 응답
- 요약문, 패러프레이징

**권장 임계값**: `avg_target_avg_similarity` ≥ 0.85

## 기본 정확도 지표

### `avg_partial_match` (부분 일치율)
- **정의**: 번역 쌍이 소스 텍스트와 얼마나 부분적으로 일치하는지의 비율
- **범위**: 0 ~ 1 (0% ~ 100%)
- **설명**: 번역문이 원문의 일부 내용을 포함하고 있는 정도를 측정합니다. 완전하지 않더라도 주요 내용이 포함되어 있으면 높은 점수를 받습니다.

### `avg_accuracy` (원문 정확도)
- **정의**: 원문 세그먼트와 번역 세그먼트 간 정확도의 평균
- **범위**: 0 ~ 1 (0% ~ 100%)
- **설명**: 예측된 번역이 원문 세그먼트와 얼마나 정확하게 일치하는지를 나타냅니다.

### `avg_target_accuracy` (번역문 정확도)
- **정의**: 번역 세그먼트와 원문 세그먼트 간 정확도의 평균
- **범위**: 0 ~ 1 (0% ~ 100%)
- **설명**: 번역문 기준으로 매칭된 쌍의 정확도를 측정합니다.

---

## 유사도 지표

### `avg_target_avg_similarity` (번역문-원문 유사도)
- **정의**: 번역 세그먼트와 원문 세그먼트 간 평균 유사도
- **범위**: 0 ~ 1
- **방법**: 토큰 기반 유사도 (Token-based Similarity)
- **설명**: 번역이 원문의 의미를 얼마나 잘 표현했는지를 측정합니다.

### `avg_target_text_similarity` (번역문 텍스트 유사도)
- **정의**: 번역 텍스트 전체의 유사도
- **범위**: 0 ~ 1
- **설명**: 예측된 번역 텍스트 전체가 원문 또는 참조 번역과 얼마나 유사한지를 나타냅니다.

### `avg_source_avg_similarity` (원문 평균 유사도)
- **정의**: 원문 세그먼트 간 평균 유사도
- **범위**: 0 ~ 1
- **설명**: 원문 내에서 각 세그먼트들 간의 유사도 평균입니다.

### `avg_source_jaccard` (원문 Jaccard 유사도)
- **정의**: 원문에 대한 Jaccard 유사도
- **범위**: 0 ~ 1
- **공식**: $J(A, B) = \frac{|A \cap B|}{|A \cup B|}$
- **설명**: 토큰 수준에서 두 텍스트 집합의 교집합 대비 합집합의 비율입니다.

## 매칭 관련 지표

### `matching_rate` (매칭율)
- **정의**: 매칭된 세그먼트 쌍의 비율
- **범위**: 0 ~ 1 (0% ~ 100%)
- **공식**: $\frac{\text{total\_matched\_pairs}}{\text{total\_gt\_segments}}$
- **설명**: 정답(GT) 세그먼트 중 실제로 매칭된 쌍의 비율을 나타냅니다.

### `matched_count` (매칭된 개수)
- **정의**: 매칭에 성공한 세그먼트 쌍의 개수
- **단위**: 개
- **설명**: 이 실행에서 매칭된 세그먼트 쌍의 절대 개수입니다.

### `total_count` (총 개수)
- **정의**: 평가 대상이 된 전체 세그먼트 쌍의 개수
- **단위**: 개
- **설명**: 평가 대상 전체 쌍의 개수입니다.

### `total_gt_segments` (총 정답 세그먼트)
- **정의**: 정답 데이터의 전체 세그먼트 개수
- **단위**: 개
- **설명**: 참조 번역에 포함된 모든 세그먼트의 총 개수입니다.

### `total_pred_segments` (총 예측 세그먼트)
- **정의**: 예측 데이터의 전체 세그먼트 개수
- **단위**: 개
- **설명**: 평가 대상 번역에 포함된 모든 세그먼트의 총 개수입니다.

### `total_matched_pairs` (총 매칭된 쌍)
- **정의**: 전체 평가에서 성공적으로 매칭된 세그먼트 쌍의 개수
- **단위**: 개
- **설명**: 원문 기준 매칭에서 성공한 쌍의 절대 개수입니다.

### `total_correct_translation_pairs` (총 정확한 번역 쌍)
- **정의**: 번역이 정확한 쌍의 개수
- **단위**: 개
- **설명**: 매칭된 쌍 중에서 번역 정확도가 높은 쌍의 개수입니다. (일반적으로 정확도 > 임계값)

## F1 및 정밀도/재현율

### `avg_f1_score` (F1 점수)
- **정의**: 정밀도와 재현율의 조화 평균
- **범위**: 0 ~ 1
- **공식**: $F1 = 2 \times \frac{\text{precision} \times \text{recall}}{\text{precision} + \text{recall}}$
- **설명**: 정밀도와 재현율의 균형을 나타내는 지표로, 불균형한 데이터셋에 유용합니다.

### `avg_source_f1_score` (원문 F1)
- **정의**: 원문 기준으로 계산한 F1 점수
- **범위**: 0 ~ 1
- **설명**: 원문 세그먼트 매칭의 품질을 종합적으로 평가합니다.

### `avg_target_f1_score` (번역문 F1)
- **정의**: 번역문 기준으로 계산한 F1 점수
- **범위**: 0 ~ 1
- **설명**: 번역 세그먼트 매칭의 품질을 종합적으로 평가합니다.

### `avg_precision` (정밀도)
- **정의**: 예측된 세그먼트 쌍 중에서 **정확한 것의 비율**
- **범위**: 0 ~ 1
- **공식**: $\text{Precision} = \frac{TP}{TP + FP} = \frac{\text{정확한 예측}}{\text{모든 예측}}$
- **설명**:
  - 시스템이 "이것이 정답"이라고 말한 것 중에 **실제로 정답인 비율**
  - 거짓 양성(False Positive)을 줄이는 능력을 평가
  - 정밀도가 높다 = 시스템의 예측을 믿을 수 있다
  - "제시된 번역이 정말 정확할 확률"

#### 예시
```
예측 결과 10개 중:
- 9개가 정답 (TP)
- 1개가 오답 (FP)

정밀도 = 9 / (9+1) = 0.90 (90%)
→ "시스템이 예측한 10개 중 90%는 정확함"
→ 신뢰도가 높음 (거짓 예측이 적음)
```

#### 언제 중요한가?
- **높은 정밀도 필요**: 법률 문서, 의료 번역 (틀린 번역이 피해를 줄 수 있음)
- **낮은 정밀도 문제**: 좋은 번역도 많이 제시되지만, 어느 것이 진짜 좋은 번역인지 신뢰할 수 없음

---

### `avg_recall` (재현율)
- **정의**: 실제 정답 쌍 중에서 **맞게 예측한 것의 비율**
- **범위**: 0 ~ 1
- **공식**: $\text{Recall} = \frac{TP}{TP + FN} = \frac{\text{정확한 예측}}{\text{모든 정답}}$
- **설명**:
  - 존재하는 정답 중에 **시스템이 맞게 찾은 비율**
  - 거짓 음성(False Negative)을 줄이는 능력을 평가
  - 재현율이 높다 = 좋은 번역을 거의 빠뜨리지 않는다
  - "정답인 번역을 시스템이 찾을 확률"

#### 예시
```
실제 정답이 100개인데:
- 시스템이 맞게 찾은 것: 95개 (TP)
- 시스템이 놓친 것: 5개 (FN)

재현율 = 95 / (95+5) = 0.95 (95%)
→ "실제 정답 100개 중 95개를 시스템이 찾음"
→ 거의 모든 좋은 번역을 놓치지 않음
```

#### 언제 중요한가?
- **높은 재현율 필요**: 검색 시스템, 추천 시스템 (좋은 결과를 빠뜨리면 안 됨)
- **낮은 재현율 문제**: 좋은 번역이 있어도 시스템이 못 찾음

---

### 정밀도 vs 재현율: 상충 관계 (Trade-off)

정밀도와 재현율은 보통 **서로 상충 관계**에 있습니다:

| 상황 | 정밀도 | 재현율 | 문제 |
|------|--------|--------|------|
| 매우 엄격한 기준 설정 | ↑ 높음 | ↓ 낮음 | 좋은 번역도 거절 (누락) |
| 느슨한 기준 설정 | ↓ 낮음 | ↑ 높음 | 나쁜 번역도 수용 (오류) |
| 균형잡힌 기준 | ≈ 중간 | ≈ 중간 | F1 점수 최대화 |

#### 구체적 예시

**상황**: 번역 정확도 임계값을 0.5 ~ 1.0 사이에서 설정

```
임계값 0.9 (매우 엄격):
✅ 정밀도: 95% (신뢰도 높음)
❌ 재현율: 50% (좋은 번역 많이 누락)
→ 문제: "완벽한 것만 골라야 하는" 상황에 적합

임계값 0.5 (매우 느슨):
❌ 정밀도: 70% (신뢰도 낮음)
✅ 재현율: 95% (거의 모두 포함)
→ 문제: 많이 수용하지만 오류도 많음

임계값 0.7 (균형):
≈ 정밀도: 85%
≈ 재현율: 80%
→ F1 점수: 0.825 (최적)
```

---

### 정밀도/재현율과 F1 점수의 관계

**F1 점수**는 정밀도와 재현율의 조화 평균으로, 둘의 **균형**을 나타냅니다:

$$F1 = 2 \times \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}}$$

#### 해석
- **F1이 높다** → 정밀도와 재현율이 모두 높음 (균형잡힘)
- **F1이 낮다** → 둘 중 하나가 극단적으로 낮음 (불균형)

#### 예시
```
케이스 1: 정밀도 0.95, 재현율 0.50
→ F1 = 2 × (0.95 × 0.50) / (0.95 + 0.50) = 0.667 (낮음)
→ 정밀도는 높지만 재현율이 너무 낮음

케이스 2: 정밀도 0.90, 재현율 0.85
→ F1 = 2 × (0.90 × 0.85) / (0.90 + 0.85) = 0.874 (높음)
→ 둘 다 비슷한 수준 (균형잡힘)

케이스 3: 정밀도 0.70, 재현율 0.95
→ F1 = 2 × (0.70 × 0.95) / (0.70 + 0.95) = 0.809 (중간)
→ 재현율은 높지만 정밀도가 낮음
```

### 실무에서의 선택 기준

#### 📋 정밀도 중심 (Precision > Recall)
**상황**: 정확성이 매우 중요한 경우
- 법률 계약서 번역 (한 글자 오역이 소송 초래)
- 의료/약품 설명서 (오류가 건강 피해)
- 금융 보고서 (부정확성이 손실 초래)

**전략**: 임계값을 높게 설정 (예: 0.95 이상만 정답)

**결과**:
- ✅ 제시되는 번역의 신뢰도가 높음
- ❌ 좋은 번역 일부가 "정답 아님"으로 처리됨
- 💡 보수적이지만 안전함

#### 🔍 재현율 중심 (Recall > Precision)
**상황**: 누락이 더 큰 문제인 경우
- 문학 작품 번역 (모든 구절 포함)
- 검색 시스템 (모든 관련 결과 반환)
- 추천 시스템 (좋은 아이템 놓치지 않기)

**전략**: 임계값을 낮게 설정 (예: 0.7 이상이면 정답)

**결과**:
- ✅ 좋은 번역을 거의 빠뜨리지 않음
- ❌ 일부 부정확한 번역도 포함됨
- 💡 포용적이지만 오류 가능성 있음

#### ⚖️ 균형 (F1 최대화)
**상황**: 둘의 균형이 중요한 경우
- 일반적인 번역 프로젝트
- 품질 관리 (정확성과 완성도 동시 추구)
- 자동 평가 시스템

**전략**: F1이 최대가 되는 지점 찾기

**결과**:
- ✅ 정확성과 완성도의 최적 조합
- ≈ 양쪽 모두 합리적 수준
- 💡 실무 권장

### 혼동 행렬 (Confusion Matrix)
정밀도와 재현율을 이해하려면 혼동 행렬이 필수입니다:

|  | 예측 정답 | 예측 오답 |
|---|---------|---------|
| **실제 정답** | TP (참 양성) | FN (거짓 음성) |
| **실제 오답** | FP (거짓 양성) | TN (참 음성) |

#### 각 항목의 의미
- **TP (True Positive)**: 정답인 것을 정답이라고 예측 ✅
- **FP (False Positive)**: 오답인 것을 정답이라고 예측 ❌ (거짓 양성)
- **FN (False Negative)**: 정답인 것을 오답이라고 예측 ❌ (거짓 음성)
- **TN (True Negative)**: 오답인 것을 오답이라고 예측 ✅

#### 정밀도/재현율 공식 재정의
```
정밀도 = TP / (TP + FP)
        → "시스템이 정답이라고 말한 것 중 진짜 정답의 비율"
        → 거짓 양성(FP) 줄이기

재현율 = TP / (TP + FN)
        → "실제 정답 중에서 시스템이 맞게 찾은 비율"
        → 거짓 음성(FN) 줄이기
```

#### 예시: 번역 평가 (100개 세그먼트)

```
예측 결과:
- 시스템이 "정답"이라고 한 것: 80개
  - 실제로 정답: 76개 (TP) ✅
  - 실제로 오답: 4개 (FP) ❌

- 시스템이 "오답"이라고 한 것: 20개
  - 실제로 정답: 4개 (FN) ❌ (놓친 정답!)
  - 실제로 오답: 16개 (TN) ✅

정밀도 = 76 / (76 + 4) = 0.95 (95%)
→ 시스템이 정답이라고 한 80개 중 76개가 정말 정답

재현율 = 76 / (76 + 4) = 0.95 (95%)
→ 실제 정답 80개 중 시스템이 76개를 찾음

F1 = 2 × (0.95 × 0.95) / (0.95 + 0.95) = 0.95
```

## 텍스트 매칭 지표

### `avg_exact_match` (완전 일치율)
- **정의**: 두 텍스트가 문자 단위로 정확히 같은 비율
- **범위**: 0 ~ 1
- **설명**: 번역 텍스트가 참조 번역과 정확하게 일치하는 정도를 나타냅니다. 매우 엄격한 기준입니다.

### `avg_text_match` (전체 텍스트 일치율)
- **정의**: 전체 텍스트가 일치하는 정도
- **범위**: 0 ~ 1
- **설명**: 원문과 번역문 전체 텍스트의 일치도를 포괄적으로 평가합니다.

### `avg_source_text_match` (원문 일치율)
- **정의**: 원문 텍스트 일치율의 평균
- **범위**: 0 ~ 1
- **설명**: 예측된 원문이 참조 원문과 얼마나 일치하는지를 평가합니다.

### `avg_target_text_match` (번역문 일치율)
- **정의**: 번역 텍스트 일치율의 평균
- **범위**: 0 ~ 1
- **설명**: 예측된 번역이 참조 번역과 얼마나 일치하는지를 평가합니다.

### `avg_segment_count_match` (세그먼트 수 일치율)
- **정의**: 세그먼트 개수가 일치하는 정도
- **범위**: 0 ~ 1
- **공식**: $1 - \frac{|gt\_count - pred\_count|}{\max(gt\_count, pred\_count)}$
- **설명**: 참조 번역과 예측 번역의 세그먼트 개수가 얼마나 유사한지를 평가합니다.

## 전역 통계

### `global_source_delta` (원문 길이 차이)
- **정의**: 예측 원문과 참조 원문의 길이 차이
- **단위**: 문자 수
- **공식**: $|len(pred\_source) - len(ref\_source)|$
- **설명**: 음수일 경우 예측이 더 짧고, 양수일 경우 더 깁니다. (절대값으로 표현)

### `global_target_delta` (번역 길이 차이)
- **정의**: 예측 번역과 참조 번역의 길이 차이
- **단위**: 문자 수
- **설명**: 번역 텍스트 길이의 차이를 나타냅니다.

### `global_source_ops_insert` (원문 삽입)
- **정의**: 원문을 참조에서 예측으로 변환하기 위해 필요한 삽입 연산의 개수
- **단위**: 개
- **알고리즘**: 편집 거리(Edit Distance) 기반
- **설명**: 예측 원문이 참조 원문에 비해 추가된 문자/단어가 있음을 의미합니다.

### `global_source_ops_delete` (원문 삭제)
- **정의**: 원문을 참조에서 예측으로 변환하기 위해 필요한 삭제 연산의 개수
- **단위**: 개
- **설명**: 예측 원문에서 삭제된 문자/단어가 있음을 의미합니다.

### `global_source_ops_replace` (원문 치환)
- **정의**: 원문을 참조에서 예측으로 변환하기 위해 필요한 치환 연산의 개수
- **단위**: 개
- **설명**: 참조 원문과 다른 문자/단어로 대체된 부분의 개수입니다.

### `global_target_ops_insert` (번역 삽입)
- **정의**: 번역을 참조에서 예측으로 변환하기 위해 필요한 삽입 연산의 개수
- **단위**: 개

### `global_target_ops_delete` (번역 삭제)
- **정의**: 번역을 참조에서 예측으로 변환하기 위해 필요한 삭제 연산의 개수
- **단위**: 개

### `global_target_ops_replace` (번역 치환)
- **정의**: 번역을 참조에서 예측으로 변환하기 위해 필요한 치환 연산의 개수
- **단위**: 개

## 행 오프셋 지표

> **행 오프셋(Row Shift)**: 테이블/문서의 행(row) 인덱스가 기준 위치에서 벗어나 있는 경우, 이를 조정하여 더 정확한 매칭을 찾는 기법

### `row_shift_applied` (행 오프셋 적용)
- **정의**: 행 오프셋이 적용된 횟수
- **단위**: 개
- **설명**: 세그먼트 매칭을 개선하기 위해 행 인덱스 조정을 시도한 횟수입니다.

### `row_shift_overlap` (행 오프셋 겹침)
- **정의**: 행 오프셋으로 인한 겹침(오버랩)의 횟수
- **단위**: 개
- **설명**: 오프셋 적용 시 이전 매칭 범위와 겹치는 경우의 개수입니다.

### `row_shift_improved` (행 오프셋 개선)
- **정의**: 행 오프셋이 적용되어 실제로 매칭 품질이 개선된 경우의 수
- **단위**: 개
- **설명**: 오프셋 적용 후 유사도나 정확도가 높아진 경우의 개수입니다.

### `row_shift_zero_eq` (행 오프셋 0 일치)
- **정의**: 행 오프셋이 0 (즉, 원래 위치)에서 일치하는 경우
- **단위**: 개
- **설명**: 오프셋을 적용하지 않아도 이미 최적의 매칭을 찾은 경우입니다.

### `row_shift_best_eq` (행 오프셋 최고 일치)
- **정의**: 행 오프셋을 적용하여 최고의 일치를 얻은 경우
- **단위**: 개
- **설명**: 여러 오프셋 값 중에서 최적의 오프셋을 찾아 적용한 경우입니다.

### `row_shift_best_avg_sim` (행 오프셋 최고 유사도)
- **정의**: 행 오프셋을 적용했을 때 얻은 최고 평균 유사도
- **범위**: 0 ~ 1
- **설명**: 오프셋 조정을 통해 달성할 수 있는 최고 유사도 값입니다.

## 편집 거리 연산 설명

편집 거리(Levenshtein Distance)는 한 문자열을 다른 문자열로 변환하는 데 필요한 최소 편집 횟수입니다:

- **삽입(Insert)**: 문자 추가
- **삭제(Delete)**: 문자 제거
- **치환(Replace)**: 문자 변경

**예시**: "ABCD" → "ACBD"
- 방법 1: B 삽입 후 D 삭제 (2회)
- 방법 2: B와 C 치환 (1회) ← 최소

따라서 편집 거리 = 1

- **활용**: 전반적인 번역 시스템 성능 평가

### 🔍 문제 진단 가이드

#### 문제 1: `matching_rate`가 낮음 (< 0.80)
**증상**: 매칭된 쌍이 적음
**원인**:
- 매칭 알고리즘 문제
- 데이터 포맷 불일치
- 세그먼트 개수 차이 큼

**해결**:
1. `total_gt_segments` vs `total_pred_segments` 비교
2. 행 오프셋 지표 확인 (`row_shift_improved`)
3. 매칭 전략 변경 (원문 기준 ↔ 번역 기준)

#### 문제 2: `avg_partial_match`는 높은데 `avg_accuracy`가 낮음
**증상**: 유사도는 높지만 정답 비율이 낮음
**원인**: 임계값이 너무 높게 설정됨

**해결**:
1. 임계값 조정 (예: 0.9 → 0.85)
2. 유사도 분포 확인 (상세 결과 참조)

#### 문제 3: `avg_target_avg_similarity`는 높은데 `matching_rate`가 낮음
**증상**: 매칭된 것들은 품질이 좋지만 매칭 자체가 잘 안 됨
**원인**: 매칭 범위가 너무 좁음

**해결**:
1. 스마트 매칭 활성화
2. 번역 기준 매칭 추가 실행 (`--no-translation-match` 제거)
